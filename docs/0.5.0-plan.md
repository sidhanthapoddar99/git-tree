# Git Tree 0.5.0 — worktrees on SSH servers

0.5.0 shows the worktrees on your SSH servers in the same graph as your local ones, as [issue #1](https://github.com/sidhanthapoddar99/git-tree/issues/1) describes: their labels in the Worktree column, their *Uncommitted Changes* rows, their branches under the host's name, and the actions to open, create and remove them. The issue is the specification of what users see. This file records how it's built.

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| What runs on the server | Only `git` and a POSIX shell, over plain `ssh`. Nothing is installed there | A helper would need installing, version matching and securing on every server, and it wouldn't make the network round trip or the server's `git status` faster. |
| Configuration | `.worktrees/git-tree.yaml` in the main worktree, read with the `yaml` package (pinned), validated against the issue's table; any other key or shape is an error that names the line | The format is public in the issue. A hand-written subset parser would reject valid YAML that people and agents write. An unknown key is an error, not ignored, so a typo never silently drops a host. |
| Where it's read | `src/remoteHosts.ts`, which owns the config, the SSH calls, each host's last state, and the fetch | One owner for everything a host has, so DataSource and the view only read its state. |
| SSH connection | `ssh -o BatchMode=yes -o ConnectTimeout=10 -o ControlMaster=auto -o ControlPersist=120 -o ControlPath=<dir>/%C <alias>`, where `<dir>` is `/tmp/git-tree-<uid>` (mode 0700) | Connection sharing turns a refresh into about one round trip. A Unix socket path is limited to about 104 bytes, and `%C` is 40, so the folder must be short; the extension's storage folder is too long on macOS. `BatchMode` makes a password prompt a *needs authentication* state instead of a hang. |
| Windows clients | The same command without the `Control*` options | Windows' OpenSSH doesn't support connection sharing, so each refresh there costs a handshake. |
| The `ssh` executable | `ssh` from the PATH, or the `git-tree.remoteHosts.sshPath` setting | Like Remote-SSH's `remote.SSH.path`, for an `ssh` that isn't on the PATH. The tests use it to point at a wrapper with a test configuration, so they never touch `~/.ssh`. |
| Status call | One SSH call per host per refresh. A fixed script goes on stdin to `sh -s`, with the repository path as its one argument, quoted for the server's shell. It prints `git worktree list --porcelain -z`, each worktree's branch tips (`git for-each-ref refs/heads`), and each worktree's `git status --porcelain` line count | The config's values never become a command: the alias is a single argument to `ssh`, and the path is a quoted argument to a script that Git Tree ships. The server counts the status lines with `wc -l`, which is what the local count does, so a worktree with 10,000 untracked files costs a number, not its file list. |
| Parsing | The local parsers: `parseWorktreeList` for the worktree list, and the same count rule as local worktrees | One parser for each format, so local and server rows can't drift. |
| Commits | `git fetch --no-tags --prune <alias>:<path> '+refs/heads/*:refs/git-tree/hosts/<name>/heads/*'`, with `GIT_SSH_COMMAND` set to the shared connection's command. It runs only when the status call's branch tips differ from the refs Git Tree already has | Git sends only the commits that are missing. The hidden refs don't appear in `git branch -a`, and the user's remotes are untouched. Comparing tips first makes most refreshes fetch nothing. `heads/` keeps branch names apart from the detached HEADs below, so no branch name can collide with them. |
| First fetch | Asks once per host, and remembers the answer in the extension's state for that repository | A fetch writes objects and refs into the user's repository. |
| Detached server worktrees | Fetch `HEAD` from the linked worktree's own path into `refs/git-tree/hosts/<name>/detached/<first 12 hex of the SHA-1 of its path>`; if that fails, the row says *commit not on this machine* | Tested against Git 2.54 with default settings: fetching the commit by hash fails ("Server does not allow request for unadvertised object"), but `git fetch <alias>:<worktree path> HEAD` works, because upload-pack run in a worktree advertises that worktree's HEAD. Folder names can repeat on one host, and paths can't. |
| Host branches in the graph | The refs read lists `refs/git-tree/hosts/<name>/heads/<branch>`, and DataSource gives them their own kind, drawn like a remote branch, labelled `<name>/<branch>`. The log includes them as start points | Server branches stay apart from local branches, and look like what they are: copies of another machine's branches. |
| Server worktrees in the view | `GitWorktree` gains `host` (the host's name, absent for local ones). The Worktree column shows `<host>:<name>`, the Worktree filter lists each host's worktrees after the local ones, and each one with changes gets an *Uncommitted Changes* row from its HEAD | The same rules as local worktrees, so the view code gains one field, not a second worktree model. |
| Never block the local graph | The view loads from each host's last state at once. A host refresh runs in the background, with a 15-second limit, and when it changes something the extension asks the view for a soft refresh | A slow or down host costs the local graph nothing. 0.4.2's tokens make the soft refresh cheap when only one host changed. |
| Failure states | Each host has one state: `ok`, `unreachable` (with the time of the last good refresh), `needs authentication`, `not a repository` (with Git's message), `different repository`, or `config error`. A host that isn't `ok` greys out its old rows | Each state comes from a distinct signal: ssh's exit code 255 and its message, `git`'s exit code, and the root-commit check. A host never looks clean when it can't be read. |
| Same project check | On the first refresh of a host, and whenever its path changes: the server's root commits must share one with the local repository | A path that points at another project would draw a misleading graph. |
| Actions | Open with Remote-SSH (`vscode-remote://ssh-remote+<alias><path>`), create and remove a worktree (`git -C <path> worktree add/remove` over the shared connection, with the local dialogs), copy the path, and a terminal (`ssh -t <alias>` that starts in the worktree) | The issue's list. Each runs only from an explicit action, and asks first as local actions do. |
| Commands | *Git Tree: Add Remote Host...* checks the connection and the project before writing the file; *Remove Remote Host* deletes the host's entry and its `refs/git-tree/hosts/<name>/` refs | The file can be written by hand or by an agent too; the commands check what a hand edit can't. |
| Version | 0.5.0 | A minor version: a new feature, no change to existing settings or workflows. |

## Phases

Each phase is its own commit, with its measurements in the message.

1. **Config.** Read, validate and watch `.worktrees/git-tree.yaml`; errors name the line. Unit tests for every rule.
2. **Status.** The SSH runner, the status script, parsing, and the host states. Tests with `ssh` mocked, then against a throwaway SSH server in a container.
3. **Commits.** The fetch, the consent, pruning, host refs in the refs read and the log, and their labels in the graph.
4. **The view.** Server worktrees in the Worktree column and filter, their *Uncommitted Changes* rows, and the failure states.
5. **Actions and commands.** Open, create, remove, copy path, terminal; *Add Remote Host...* and *Remove Remote Host*.
6. **Docs.** The README section and the agent instruction from the issue.

## Measured so far

A prototype of the status script, against an SSH server in a container on this machine (Git 2.54, one repository with a main and a detached linked worktree), median of 5 runs:

- One status call without connection sharing: 130 ms, nearly all of it the SSH handshake.
- With connection sharing: 18 ms.
- Its answer: 355 bytes.

Across a network, add one round trip to the shared figure, and the handshake's two or three round trips to the other.

The path is passed in single quotes, with each `'` written as `'\''`. That reads the same in sh, bash, zsh, fish and csh, which covers the login shells `ssh` might start. The config rejects a `path` that isn't absolute or holds a control character, so a path can't end the quoted argument.

## Measure

On the test server, with connection sharing and without: the time and bytes of one status call, of a refresh where nothing changed, and of a fetch after one new commit. And the local view load with two hosts configured, against no hosts, which must not grow.

## As built

Where 0.5.0 differs from the decisions above, and why:

- **The worktree list is read without `-z`**, so the server's output goes through `parseWorktreeList`, the parser local worktrees use. A path with a newline breaks both the same way.
- **The status script takes four arguments**: the path, the untracked-files mode, whether to list linked worktrees, and whether to print the root commits. The roots are printed only for the same-project check, because `git rev-list --max-parents=0` walks the whole history. It runs `git --no-optional-locks status`, so it never writes the server's index.
- **A fetch has its own 5-minute limit**, apart from the status call's 15 seconds: a first fetch can be large. A refresh asked for while one runs queues one more, so the view never keeps data read before an action.
- **A detached worktree whose commit isn't here** says *commit not on this machine* in the Worktree filter, not in a row: an *Uncommitted Changes* row needs its commit in the graph.
- **Host branches show even when *Show Remote Branches* is off.** They are their own kind, and a host's state should always be visible. Each host in the config adds its own `--glob` start point, so the refs of a removed host never do.
- **Hosts refresh** when a view opens a repository or becomes visible, on the Refresh button, and on the optional interval; not on every file change, which would make an SSH call per save.
- **A host that needs authentication is left alone** for 30 seconds, doubling after each failure up to 5 minutes. OpenSSH 9.8 and later refuse new connections from an address after repeated failed logins (`PerSourcePenalties`), which would also lock out the user's own `ssh`.
- **SSH aliases must match `[A-Za-z0-9_][A-Za-z0-9._@-]*`**, which rules out option injection (`-o…`) and the `:` that would break `alias:path`. Host names that differ only in case are an error, because their refs would clash on case-insensitive file systems.
- **Git Tree warns once** when Git tracks `.worktrees/git-tree.yaml`.
- *Allow Fetching...* in the Worktree filter and the worktree menu asks again for a host whose first fetch was declined.

Measured against the test server (loopback, median of 9): a status call takes 16 ms with a shared connection and 178 ms without; a refresh where nothing changed 19 ms and about 3.3 KB on the wire; a refresh after one new commit, with its fetch, 130 ms and 8.3 KB. The local view load with two hosts of three worktrees each: 6.2 ms against 5.8 ms with none, on a 569-commit repository.
